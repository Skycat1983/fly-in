## Reconstructed work so far

The parser and graph are implemented and tested. `RouteFinder` uses Dijkstra's
algorithm to find one route. It stores best known costs in `distances`, the
preceding hub in `previous`, and finished hubs in `visited`. When a cheaper
route is found, the predecessor changes. Reconstruction follows predecessors
from the end back to the start and reverses the result. The finder uses the
actual endpoint names, skips blocked hubs, and charges 2 turns to enter a
restricted hub. Its tests cover those cases, disconnected maps, and stable
equal-cost results.

The route finding boundary is now clear: it returns `list[str]`, including both
endpoints, or `[]` if unreachable. The simulator can use `Graph.get_hub(name)`
to inspect zone metadata. No drone position or turn state belongs in the
route finder. This resolves several questions in the old next-steps draft.
